## KI-001 启动路径同步读取 person-cards.json

- **状态**：未修复
- **位置**：`src/host.js:139-143`（`createHost`）
- **复现**：`activate()` → `createHost()` → `readFileSync(person-cards.json)`

## KI-002 数据目录解析静默回落

- **状态**：未修复

## KI-005 抽取召回低

- **状态**：已测量并修精度（2026-10-30，0.23.13）；召回低主要是语料性质，不是规则缺陷
- **位置**：`src/extract.js` 规则表
- **实测（线上 84 条主人事件 / 70 条有实义句）**：命中 10，原始召回 14%；
  去掉媒体噪声（14 条 `[图片]`/`[拍一拍]`）后仍是 14%
- **关键判断**：60 条漏句里绝大多数是寒暄、问句、临时决定（"在嘛""晚安""今天天气不错""我想吃汉堡王"），
  **不该**进长期记忆。逐条看下来真正该抽漏掉的只有 1 条（"香菜我不吃"），已补规则
- **修掉的 3 个假阳性（比召回更重要）**：
  1. `correction` 把影评句子"不是发明，是把废料场里的零件重新排成…"抽成事实改判 →
     加限制：被纠正项/纠正值必须是 ≤12 字名词性短语，且不以 在/把/被/是… 开头，不以 这/那/它 指代
  2. `correction` 的陈述语义写反了（"不是A，而是B"被写成"A 不是 B"）→ 改为"不是A，是B（主人纠正）"
  3. `boundary` 把罗列句抽成"主人要求不要接入、封号风险…" → 含顿号或 >20 字不再算边界
- **新增窄规则**：宾语前置 `X我不吃/我不喜欢` → "主人不喜欢X"（唯一一条从真实语料补的规则）
- **已产生的假记忆**：`笑→在惊讶（主人纠正）` 已于 2026-10-30 21:21 退役（追加 `retired` 修订，
  rev2，历史行保留；`scripts/retire-cognition.mjs`）。验证：`verify-memory-tools` 12/12，
  observation 里能看到 rev2 与退役原因，audit trail 完整
- **工具**：`node scripts/audit-extraction.mjs --data-dir <core> --admin <QQ>` 只读审计召回与漏句
- **未做**：不引入后台 LLM 自由总结；value/commitment 仍不启用

## KI-010 约定与关系（C/D）

- **状态**：0.23.15 上线抽取与存储，0.23.16 补撤销、场景字段与只读视图；明确不做的事写在下面
- **位置**：`src/extract.js`（relationship-* / agreement-* / revoke-* 规则）、
  `src/consolidation-pipeline.js`（attrs 落库、撤销通道）、`src/memory-view.js`（describeTerms）
- **已做**：
  1. 四类关系句式（你是我的X / 我把你当作X / 你就像我的X一样 / 我们是X）→ `attrs { role, subject, object }`
  2. 三类约定（称呼 call / 格式 format / 定时规则 rule）→ `attrs { rule, value, scenario }`
  3. **撤销**：`我们绝交/结束扮演/做回助手` 退役该会话全部关系；`以后不用加颜文字了` 按内容匹配退役那条约定。
     撤销只追加一个 retired 修订，不写新条目、不删历史
  4. 引用他人语句（`[引用 …]`）与 @ 提及剥离后再匹配；问句不算陈述；角色名必须是名词
  5. `cognition_mem_terms` 只读视图：关系与约定分表列出（状态/场景/证据数）
  6. **期限**：`到下周五为止 / 截止到月底 / 直到年底 / 三天内 / 两周内 / 一个月内` 解析成 `attrs.expiresAt`，
     到期在巩固时自动退役；只对 Asia/Hong_Kong 生效（无夏令时），其它时区不解析
  7. **覆盖**：新的称呼/格式约定顶掉同 scope 同类型的旧约定（`superseded by newer agreement`）
  8. **场景排序**：注入时 `scenario` 命中给 15 分加成，只影响顺序，不排除条目
- **未做（明确取舍）**：
  1. **时限只认几种说法**：`明年的某个时候`、`等我毕业` 这类相对事件不解析；超过 365 天不猜
  2. **场景不做硬过滤**：不会"写代码时才加载 code 约定"，只是把它排前面
  3. **不做全局人设注入**：关系只作为普通认知，本轮话相关才注入；这是"不恢复人设卡"的硬约束
  4. **role 是字面抽取**：`你是我的充电宝` 这类比喻也会被抽成角色；`我们绝交` 是全局退役，玩笑话也会执行
     （靠 append-only 修订 + 备份可回退）
  5. **语气/权力级差（tone）没抽**：需要模型判断，规则层不做
  6. **冲突只看"同类替换"**：同一件事的正反约定（"必须加表情" + "不许加表情"）不会互相裁决，只会各存一条
- **风险与恢复**：误抽的 relationship/agreement 会直接 stable（因为是指令）。撤销误操作靠
  `scripts/retire-cognition.mjs` 或直接看修订历史；数据 append-only，任何一次退役都能看到前一条
- **下一步（v2 候选）**：时限解析、场景匹配执行、约定冲突检测（同一规则两条相反约定）、tone
