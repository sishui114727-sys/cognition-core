# 记忆生长链路 · 设计与实现

更新时间：2026-10-29
版本：0.22.0
上游设计：《学习型认知插件_管线设计》（L0–L6 分层、人格稳定条件）
实现：`src/episode-builder.js`、`src/extract.js`、`src/consolidation-pipeline.js`

---

## 一、这条链路解决什么

之前只会：

```text
after-response → dialogue Event
```

现在补上后半段：

```text
dialogue Event
  →（分组）Episode
  →（抽取）候选 Cognition
  →（证据累积/跨情境）stable Cognition
  →（门控）SelfModel 新版本
```

四条硬约束（来自交接文档与工程铁律）：

```text
不恢复人设卡
不自建 LLM 调用、不猜内容
SelfModel 不自动注入、只慢更新、每次变更留证据
不删本地数据
```

## 二、关键决策与理由

### 1. 抽取用规则，不调模型

插件里没有可靠的 LLM 通道；就算有，也不该让模型在后台"总结对话成人格"——那正是交接文档要求避免的黑箱。

所以：**只记录用户显式说出的话**，规则命中才算证据。召回率低是刻意取舍：

```text
宁可少记，不可错记
每条 cognition 都能指回原文事件
```

代价写进 §七 已知限制，不隐藏。

### 2. 只从主人发言抽取

`event.participants` 含 `adminId` 的事件才进入抽取。

理由：

```text
群聊里任何人都能说"记住…" → 不设限就会被人写进记忆（可被利用）
非主人的偏好属于关系认知，不是自我模型素材
```

非主人事件只参与 Episode（叙述），不产出 Cognition。

### 3. Episode 是"时间段 + 同一会话"

分组规则（`DEFAULT_EPISODE_POLICY`）：

```text
同一 scope（group:<id> / person:<id>）
相邻事件间隔 ≤ 30 分钟
单集 ≤ 20 条事件
单集至少 2 条事件（单条不成立）
```

单条事件不建 Episode：一次搭话不构成"经历"。

### 4. 晋升要跨情境

`evaluatePromotion` 增加 `minContexts`（默认 1，保持旧行为；流水线传 2）。

"情境" = `scope` + 日期。同一句"我喜欢猫"今天私聊说明天群里说，算 2 个情境。

置信度阶梯（写死在代码，不进配置）：

```text
首次出现            0.65   # 可能是玩笑、反讽、口误
每多一个独立情境    +0.10
上限                0.90
```

`0.65 + 0.10 = 0.75` 正好等于"两个情境"——阈值不是拍的，是这个阶梯的推导结果。

### 5. SelfModel 只收三类认知

进 SelfModel 必须同时满足：

```text
status = stable
kind ∈ {value, commitment, boundary}    # 偏好/事实不进自我模型
contexts ≥ 2
confidence ≥ 0.75
contradictions 为空
证据里含主人
```

且：

```text
每次最多加 3 条
条目原文照抄 statement，不改写
不删、不改旧条目
一次运行只产生一个新版本，change.reason + change.evidenceIds 记全
```

这就是"人格稳定条件"的代码化：单次事件不会改变自我模型。

### 6. 主人纠正直接生效（唯一例外）

`不是A，而是B` 这类纠正，是主人的权威输入：

```text
kind = fact, confidence 0.9, status 直接 stable
changeReason: owner-correction
```

理由：`学习型认知插件_管线设计.md` 把"管理员纠正"列为一等来源；如果还要等两次跨情境，纠正就永远不生效。

这不违反"单次事件不改人格"——纠正只产生 Cognition，进 SelfModel 仍然要过 §5 的门控。

### 7. 配置只放开关，阈值在代码

| 进配置 | 不进配置 |
|---|---|
| `consolidateEnabled`（默认 **false**） | 分组间隔、单集上限 |
| `consolidateIntervalMin`（默认 30） | 置信度阶梯、晋升阈值 |
| | SelfModel 门控条件 |

默认关闭的原因：这条链路会往真实记忆里写记录。先 dry-run 看输出，再开开关。

## 三、数据流与幂等

```text
runConsolidation({ core, now, policy, dryRun })
  1. events = store.readAll() filter source.type === 'dialogue'
  2. covered = existing episodes 的所有 eventIds
  3. drafts = buildEpisodes(events 未覆盖部分)
  4. 非 dryRun：episodes.append(draft)
  5. candidates = extract(owner 事件)
  6. merge：按 metadata.key = scope|kind|object 归并证据
     新证据为空 → 不写、不涨 revision
  7. promote：候选逐条过 evaluatePromotion(含 minContexts)
  8. selfModel：门控通过且文本未存在 → 一次版本更新（≤3 条）
```

幂等保证：

```text
Episode      靠 covered eventIds 去重
Cognition    靠 metadata.key + 证据并集；无新证据不写
晋升         已 stable 不再参与
SelfModel    条目文本已存在则跳过
```

同一份数据连跑两次，第二个 run 的写入数是 0——这条有测试。

### 回滚

数据是 append-only，回滚 = 再写一条新版本：

```text
Cognition    append 旧内容，changeReason = rollback
SelfModel    append 旧 version 的 values/commitments/boundaries，version+1
```

不提供物理删除；需要彻底移除时由人拿备份处理。

## 四、调度

```text
after-response 写入 dialogue 事件后
  → maybeScheduleConsolidation()
  → 若 consolidateEnabled 且距上次 ≥ interval
  → setTimeout(0).unref()：不阻塞回复、不持有进程
  → deactivate 时 clearTimeout（注册/卸载成对）
```

启动路径不动：没有顶层 IO、没有 timer，只有一次设置读取。

手动入口（owner-only）：

```text
cognition_consolidate { dryRun?: boolean }
scripts/consolidate.mjs --data-dir <dir> [--dry-run] [--apply]
```

## 五、验收

```text
能列出 Episode，且每条都能指回事件
每条 Cognition 有 evidenceEventIds + status + confidence
候选人晋升为 stable 时，证据数 ≥2 且跨 ≥2 情境
SelfModel 有 version、change.reason、change.evidenceIds
同一个 run 重跑不产生新写入
dry-run 不写任何文件
1k 事件量级单次 run < 300ms
```

2026-10-29 实测（真实数据副本，2.87 MB / 20 条 dialogue）：

```text
Episode        4（--apply 写入）
Cognition      0（主人 6 条发言 0 命中，见 KI-005）
SelfModel      1 → 1
单次 run       30–48ms
重跑           0 写入（幂等）
dry-run        文件行数不变（测试覆盖）
```

单测现状：75 项全绿，其中 10 项链路 + 1 项 host 集成。

## 七、语境口径（2026-10-30 线上定稿）

晋升要求 `证据 ≥2 且语境 ≥2`，而**语境的实现是 `scope + 日期`**（`consolidation-pipeline.js` 的 `addContext`）。

```text
同一天说一百遍       → 证据涨、语境仍是 1 → 不晋升
隔一天再说一遍       → 语境变 2 → 晋升
私聊 + 群聊各一次    → scope 不同 → 语境 2 → 晋升
```

代价与选择：真实聊天里同一天重复同一事实很常见，这条口径会让事实类晋升偏慢。
2026-10-30 线上实测（`未来 是主人`：ev=4 / ctx=1 未晋升）之后，主人明确选择**保持现状**：

```text
A. 跨天才晋升（采纳）        慢，但不容易被一次对话里的自说自话骗到
B. 同一天 3 条独立消息即晋升  未采纳
C. 同一天 2 条即晋升          未采纳
```

如果以后要放宽，改动点是 `addContext()` 的口径 + 一条新护栏（同一天最多计一次），
不要直接改 `minContexts` 阈值——那会同时放松偏好类与事实类，两类风险不同。

## 八、已知限制

1. **召回低**：规则只覆盖显式句式，含蓄表达、反问、玩笑不会进 Cognition。
2. **主语不解析**：抽取默认主语是主人；"XX 喜欢 Y"这类第三方偏好不抽取。
3. **矛盾检测弱**：只处理"不是 A，而是 B"显式纠正，不处理隐式冲突。
4. **全量读 events**：每次 run `readAll()` 解析整个 `events.jsonl`（当前 2.87 MB），随增长线性变慢；已登记 KI-004。
5. **Episode 无跨天合并**：跨午夜的一段对话会被切成两集。

这些限制是刻意的，先保证"不错记"，再谈"记得多"。
