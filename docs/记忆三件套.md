# 记忆三件套（0.23.0）

三个只读工具，把记忆分成三个粒度暴露出来。目的不是"让模型看见更多"，而是**让每一句结论都能一路查到原话**。

```text
cognition_mem_timeline      什么时候聊过什么
cognition_mem_observation   提炼出了什么结论、证据链、版本历史
cognition_mem_raw           原话到底怎么说的
```

三个都 **owner-only**：原话属于隐私内容，群成员即使能触发机器人也读不到别人的会话。

## 1. cognition_mem_timeline

参数：`days`（默认 7，上限 90）、`limit`（默认 30，上限 100）、`kinds`（event/episode/cognition）、
`query`（关键词过滤）、`scope`（默认当前会话）。

输出按天分组、时间倒序，每行带 id：

```text
# 2026-10-30
12:48  event      dialogue:private:10001:1793335728430  似水未来: 我想睡觉了
12:48  event      dialogue:reply:private:10001:1793335722393  我: 天气好就该出门晒晒…
12:47  cognition  cog_559787cd-…  [candidate] 主人不喜欢香菜
12:47  event      dialogue:private:10001:1793335636233  似水未来: 今天天气不错
```

**默认跳过只含一条原话的剧集**：一条消息也会生成一个剧集，不跳过的话时间线会把同一句话显示两遍
（真实数据里 12:47 那条就同时有 event 和 episode）。要看全部时传 `minEpisodeEvents: 0`（脚本层）。

## 2. cognition_mem_observation

参数：`id`（`cog_…` 或 `ep_…`；留空列出当前会话的条目供挑选）。

```text
认知 cog_a147626d-… · rev 3 · stable/preference
结论：主人喜欢睡觉
主体：主人 · 关系：喜欢 · 客体：睡觉
置信度：0.75 · 首次 2026-10-29 11:36 · 最近确认 2026-10-30 12:18
最近变更原因：promoted: evidence=2 contexts=2
证据：2 条原话 · 0 个剧集
  dialogue:…  2026-10-29 23:10  似水未来: 我喜欢睡觉
  dialogue:…  2026-10-30 01:02  似水未来: 早点睡
版本历史（3）：
  rev3 … stable/preference ev=2 promoted: evidence=2 contexts=2
  rev2 … candidate/preference ev=2
  rev1 … candidate/preference ev=1 extracted:preference
```

**证据缺失会显式标出来**：`evt_x [证据缺失]` 并追加 `⚠ N 条证据引用找不到对应记录（历史迁移或已被删），结论存疑。`
静默丢证据比没有证据更危险——这条规则在这里比"输出好看"优先。

## 3. cognition_mem_raw

参数：`ids`（事件 id，逗号分隔，最多 10 条）。

```text
原话 dialogue:private:10001:1793334842420
时间：2026-10-30 12:34 · 范围：person:10001
来源：dialogue · 隐私：private · 显著度：0.50
参与者：10001(speaker)
对话原文：
  似水未来: （🤔）我讨厌香菜
其他字段：chatKey, replyMissing
```

有 `metadata.turns` 时逐条渲染（带媒体标记），没有就退回 `text`——旧事件没有 turns，仍然可读。

## 验证

```text
node --test test/memory-view.test.mjs          8 项（单位）
node --test test/host.test.mjs                15 项（含 owner-only 与三工具联动）
node scripts/verify-memory-tools.mjs          真实数据只读副本，12 项断言
```

`verify-memory-tools.mjs` 不写线上文件：数据先复制到临时目录，面板快照也写临时目录。

## 已知限制

- 时间线的 `query` 是**字面过滤**，不是语义检索（语义召回是另一件事，未做）。
- 观察层只读；改结论仍然只走巩固流水线（`cognition_consolidate`）。
- 三件套不解决"注入什么"的问题，只解决"查得到、对得上"。
- 事件 id 由宿主提供（形如 `dialogue:private:…`），不是 `evt_` 前缀；工具按"存储里的 id"原样匹配。
