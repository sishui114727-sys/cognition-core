# 炸机说明（必看！！！！）

版本：`0.23.21`  
适用：QQ Agent（QQA）+ cognition-core 社区版首次装载  
一句话：**装它之前先把记忆/人设类插件清干净，装完之后别同时开两套认知。**

# 一、会打架的插件

下表的插件名来自真实装载环境（`/api/skills` 实际列表），不是举例。

## 1. 必须停用（与 core 双写或双注入）

| 插件 | 它干什么 | 和 core 冲突在哪 | 后果 |
|---|---|---|---|
| `mem-layered` | 分层长期记忆 | 与 Event/Cognition 双写 | 同一条消息记两份，检索互相打架 |
| `cross-memory` | 跨会话联想记忆 | 与 Event 检索重叠 | 跨会话边界被它绕过，A 群的话出现在 B 私聊 |
| `life-memory` | 仿真实生活注入 | 每轮注入生活设定 = 人设卡 | system prompt 固定膨胀，人格漂移 |
| `cross-chat-link` | 跨会话认人 | 与 Person 重复 | 认人结果两套，互相覆盖 |
| `context-reuse` | 伪 session 历史插入 | 改写首条 user 消息 | 破坏前缀，缓存全失效，成本飙升 |
| `memory-recall` | 旧记忆检索 | 与 `cognition_recall` 语义重复 | 模型随机挑工具，回忆结果不可预期 |
| `owner-identity` | 旧主人识别 + 主人人设 | 与 Identity Anchor / Person 重复 | 可注入主人人设，owner-only 判定被搅乱 |

这七个在本机当前都是 `active=false`。**如果你之前装过，确认它们是停用状态，而不是被删了又装回来。**

## 2. 建议停用旧工具（保留插件本体）

| 插件 | 保留什么 | 关掉什么 | 原因 |
|---|---|---|---|
| `sticker` | 表情库/收藏 | `sticker__send_sticker` | 绕过 ActionBus，动作不进审计 |
| `qzone` | 选题、配图、评论读取 | `qzone__publish_qzone_post` | 绕过确认与权限等级直接发公共内容 |
| `qq-self` | 读取自身状态 | `update_profile` / `publish_dynamic` | 会改写身份字段，与 SelfModel 抢"我是谁" |

## 3. 开着但要知道它会咬人

| 插件 | 风险点 | 建议 |
|---|---|---|
| `context-chime` | 也判断"要不要接话"，与 core 的主动发言门槛是两套判定 | 只留一套；否则可能被叫两次或该叫不叫 |
| `burst-merge` | 合并连续消息 → 一条消息不再对应一条 Event | 合并后事件粒度变粗，"一条消息只记一条"的假设会松 |
| `cache-guard` | 会清理缓存/临时目录 | 确认清理范围不含 `data/plugin-data/cognition-core` |
| `self-fix` / `self-doctor` / `extension-forge` | 会改插件文件或配置 | 它们改完 core 的文件，再出问题很难归因；出问题先看它们动过什么 |
| `desktop-control`（10 个工具） | `pc_run` 能执行命令 | core 的权限闸门**管不到别的插件**，别以为 L2 就等于安全 |
| `mobile-control`（20 个工具） | 手机自动化 | 同上，且更容易被聊天内容里的指令诱导 |
| `agent-reach` | 读网页/RSS | 提示注入入口；读回来的内容对它来说是指令，对 core 是数据 |
| `meme-taste` | 可能改写 system prompt | 若保留，确认它没在改 prompt；否则人格来源又多一个 |
| `gpt-sovits-tts` / `cover-pipeline-2` | 重 CPU/GPU | 不抢数据，但会拖慢整机与首响；高负载时记忆写入延迟上升 |

## 4. 明确不需要动的

```text
speaker-identity   只做稳定 QQ 身份标注，不写记忆
silence-ping       只判断是否静默，不写记忆
gallery / wallpaper / image-compat / desktop-pet    纯展示
calculator / help-board / schedule / api-beggar     与本插件无关
ban-state / account-pool / dev-orders               运维类
```

# 二、配置层必须清空

```text
persona.roleText              = ""
persona.customRules           = ""
persona.systemPromptOverride  = ""
personaByChat                 = {}
customPersonas                = []
```

保留（这些只是账号名/运行参数，不是人设）：

```text
persona.botName
persona.selfNickname
persona.participation
```

**为什么必须清**：core 的表达是运行时按记忆生成的。人设卡还在，它就会一边按记忆说话、
一边被固定人设拽回去，表现为"人格不稳定"。这不是 bug，是两个来源在抢方向盘。

# 三、装载顺序（照做，别跳步）

```text
1. 完全退出 QQ Agent（任务管理器确认没有 QQ Agent.exe）
2. 备份 data/ 和 config.json
3. 停用上表第 1 节的七个插件（不是删，是停用）
4. 关掉第 2 节的旧工具
5. 清空第 2 节的人设配置
6. 把 plugin/ 放进 resources/app/plugins/cognition-core
7. 启动 QQA
8. 确认插件列表里 cognition-core active，工具数 16
9. 设置里填主人 QQ、权限等级从 L2 开始、打开"启用认知核心"
10. 私聊说一句话，打开面板确认已被记录
11. 观察 24 小时：有无重复记录、有无乱接话、有无重复注入
12. 稳定后再逐步开公共动作（B站评论 / 空间发布）
```

不要先删数据再验证。不要一次开满权限。

# 四、装载后可能出现的具体问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 工具列表里没有 cognition-core | 目录层级错（多套了一层）、宿主版本太老、`plugin.json` 被改坏 | 目录应是 `plugins/cognition-core/plugin.json`；看日志里有没有 `加载成功：认知核心` |
| 面板显示"示例数据" | 插件还没写出快照 | 启用插件、产生一次会话、重新打开面板 |
| 面板空白 / 404 | 直接开了 `panel/overview.html` 但插件目录被移动 | 从设置里的"打开权限面板"进 |
| 一条消息被记两次 | 装了 `mem-layered` 或旧版遗留状态文件 | 停用冲突插件；检查 `inject-state.json`；用 `dedupe-events.mjs` 迁移 |
| 同一段记忆连续几轮重复出现 | 注入去重状态没落盘（旧版本问题）或被 `cache-guard` 清了 | 确认版本 ≥0.23.7；把 core 数据目录排除出清理范围 |
| 群里疯狂接话 | `context-chime` 与 core 同时判定，或时间窗/上限没配 | 只留一套接话判定，收紧时间窗与日上限 |
| 它开始说固定口癖 / 提到"设定里" | 人设卡没清干净，或 `life-memory` 还在注入 | 按第二节清空；确认 life-memory 停用 |
| 回复变慢、首响很久 | `cover-pipeline-2` / `gpt-sovits-tts` 占满 CPU/GPU | 错峰；或先停掉不用的重插件 |
| 权限等级 L2 但它执行了危险操作 | 那些操作来自 `desktop-control` / `mobile-control`，不受 core 管控 | core 不是沙箱；要么停用这些插件，要么接受风险 |
| 重启后设置回到默认 | 设置保存后没重载，或配置文件被 `self-fix` 改过 | 保存后重启一次；查 `self-fix` 日志 |
| 记忆检索结果明显变差 | `mem-layered`/`cross-memory` 双写导致同义条目互相稀释 | 停用冲突插件后跑 `node scripts/eval-retrieval.mjs` 对比基线 |
| 发空间失败 / 被平台拦 | 平台限流、登录失效、内容审核 | 看审计日志里的失败原因；不要反复重试触发风控 |

# 五、风险说明

## 1. 隐私风险

核心会保存：触发文本、她的回复、人物身份、关系边界、印象、动作审计。本地 JSONL 也是敏感数据。

```text
同一台电脑的其他用户可读
备份/网盘同步会复制
日志/截图/导出文件可能泄露
群聊内容包含第三方隐私
```

建议：独立系统账户、磁盘加密、备份加密、不要把 `data/` 放进公开仓库。

## 2. 群聊第三方数据

群友没有同意被记录。聚合导出脚本只输出计数，不输出正文；
以后若想要原始对话，必须另立协议、逐人同意，不能沿用本版协议。

## 3. 公开发布风险

空间、评论属于公共动作：发出后可能被截图/转发/索引，删除不保证彻底，平台可能限流/封号。
当前保护是 owner-only + L3 + 确认 + 内容过滤，但**不保证平台侧一定成功、一定可删除**。

## 4. 平台条款风险

B站、小黑盒、QQ空间接口可能变更、加验证码、限流、封禁、要求登录、禁止自动化。
本项目不保证长期可用，也不授权绕过平台限制。

## 5. 动作风险

ActionBus 不是操作系统沙箱：插件仍以 QQA/Node 进程权限运行，文件系统无内核级隔离，
网络请求由宿主进程发出。有权限等级/时间窗/限额/冷却/确认/审计，
但没有独立账户、容器、强制代理、文件系统白名单。**别把它当安全边界。**

## 6. 提示注入风险

聊天内容、网页、B站简介、小黑盒帖子、空间评论都可能包含指令。可能的诱导：
调用工具、泄露上下文、发公开内容、读不该读的数据。
缓解：工具 owner-only、公共动作确认、权限等级、内容过滤。过滤不是万能的，尤其语义绕过。

## 7. 模型错误风险

认错人、编造记忆、错误总结、把群聊内容带进空间、把私聊内容说给群里。
缓解：Person/Relationship 只按稳定 ID、认人卡片只追加、群聊不注入私聊印象、空间隐私过滤。
不能保证 100%——**看到明显不对的记忆，用 `cognition_mem_raw` 查证据，别信嘴。**

## 8. 数据导出风险

k=5 小样本抑制，只输出计数/分类。但总用户极少时，某些分布仍可能被推断。

## 9. 升级与兼容风险

```text
QQA 升级会覆盖顶栏补丁
插件 API 可能变化
旧 qzone/sticker 工具可能改名
设置保存后不自动重载
```

必须保留：备份、版本号、变更日志、回滚包。

## 10. 数据丢失风险

append-only 降低覆盖风险，但不等于备份。磁盘损坏、误删 `data/`、JSONL 写坏、
手动 dedupe/迁移都会丢数据。请定期备份并验证恢复。
