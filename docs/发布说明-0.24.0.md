# 发布说明 0.24.0 — 让记忆核心读得到学习管线

**一句话：这一版多了一个只读的桥——记忆核心能搜她的手账、稿件、札记，但不写它们。**

上一版（0.23.22）把"记得对不对"变成了可对账的事。这一版解决另一半：她写下来的东西（手账 / 取到的稿件 / 札记）原本只在学习管线里，问"上次那个讲意义的视频"，记忆核心是查不到的。现在能查了。

---

## 一、这一版做了什么

| 变化 | 具体 |
|---|---|
| 新的检索工具 | `cognition_study_search`：搜手账 / 稿件 / 札记，返回 id、日期、片段 |
| 回忆带尾巴 | `cognition_recall` 命中记忆时，末尾追加一句"学习管家里也有…"；**记忆里没有**可靠内容时，如实说"记忆里没有，但学习管家里有" |
| 同义词扩展 | 复用核心自己的 `SYNONYM_MAP`，问"疲惫"能捞回写着"累了"的手账 |
| 修订折线程 | 手账是追加修订的，同一篇的原条目 + 修订折成一条，只取最新一版 |
| 默认关闭 | `studyBridgeEnabled` 出厂 `false`；不打开就是原来那个核心 |

工具数 16 → 17。

## 二、桥的边界（先说不做什么）

```text
只读        不写手账、不改索引、不动账本。手账的唯一写入者仍然是学习管线
不合并      手账不进 events.jsonl。学习记录不是对话记忆，混进去会让提取、归纳、注入一起变脏
默认关闭    装上升级不会静默改变任何一轮对话
词面匹配    不做向量。同义改写要靠同义词表，表里没有就搜不到
不解决回写  手账里想引用记忆，仍然只能靠对话
```

为什么不做"写进核心"：核心的写入口只有一条（宿主回调 + 回应后处理）。从隔壁插件直接写它的 JSONL，等于破坏"只有一个写入者"——这是最难查的一类问题；而且卸掉学习管线后，核心会留下半条残废记忆。

---

## 三、读哪些文件

```text
<学习管线数据>/journal/ledger.jsonl        手账账本（唯一真相）
<学习管线数据>/readings/readings.jsonl     稿件
<学习管线数据>/notes/notes.jsonl           札记
```

数据目录默认取核心数据目录旁边的 `cognition-study`，可以用 `studyDataDir` 覆盖。目录不存在 = "现存 0"，从不抛错；账本坏行跳过，不整份失败。

缓存按 `(mtime, size)` 失效：回忆是高频调用，不能每次重读几千行账本。

---

## 四、检索口径

```text
切词     中文二元组、英文与数字按词
权重     标题 3 分 / 正文 1 分；近义词低一档（标题 2 / 正文 1）
门槛     原词覆盖率 ≥ 0.3；原词一个都没命中时要求 ≥ 0.67
排序     分数高者先出
上限     默认 5 条，最多 10 条
```

两条门槛是有原因的：

- 0.3 挡住"只沾一个词"的噪声；
- 0.67 挡住混问——问"疲惫 区块链 量子计算"时，一个近义词不能把一条无关记录端上来。

## 五、实测（真实数据，不是构造用例）

在部署副本 + 真实核心数据副本 + live 学习管线数据上跑过：

```text
cognition_study_search "意义"
  学习管线命中 2 条（现存 手账 1 篇 / 稿件 1 篇 / 札记 0 条）
  - [手账] 2026-10-31 《意义比幸福更耐放（TED · Emily Esfahani Smith）》id: j:2026-10-31:dac4e2e865
  - [稿件] 2026-10-31 《【TED演讲】必看100场TED演讲合集…》id: r:BV1UbyZB9ERb:1:217975bb

cognition_recall "意义的四个支柱"
  E: 诶…链接好像没跟着过来，我这边只看到"给你链接"四个字
  学习管线（她的手账 / 稿件 / 札记）里也有：
  · [手账]《意义比幸福更耐放》 2026-10-31 j:2026-10-31:dac4e2e865
  · [稿件]《必看100场TED演讲合集》 2026-10-31 r:BV1UbyZB9ERb:1:217975bb

桥关闭后
  工具 →「读取学习手账」没打开    回忆 → 正常，不含学习管线段
```

回忆那段的关键在**分开说**：记忆里没有可靠内容，就说没有；但手账里有，就给 id。不合并成一句"应该有点印象"。

## 六、这一版踩过的坑（写出来，免得下一个插件再踩）

三个 bug 都是真实数据打出来的，而且**单测当时全绿**：

| 坑 | 表现 | 教训 |
|---|---|---|
| 目录猜错 | 稿件永远 0 篇 | 路径要从对方的 live 目录抄；夹具也要按真实布局造 |
| 字段形状猜错 | `keyPoints` 是 `[{at, text}]`、`keywords` 是 `{term, count}`，按字符串写会打印 `[object Object]` | 跨插件字段形状必须抄真实数据 |
| 修订没折线程 | 同一篇被端上来两三次，先出的常是被改掉的那版 | 追加式存储要先想清楚"哪一条代表当前状态" |

还有一件不是 bug 但更值得记：字幕会骗人。同一场演讲重复取稿，B站 AI 字幕分别返回过 260 / 416 / 428 / 1476 段，也返回过 6 段 30 字且内容完全无关的片段。所以"读完了"必须能追到具体那段正文——`coverage` 和升级路径只能兜到这一步，兜不到"字幕本身是错的"。

```text

数据目录不是默认位置时，在「学习管线数据目录」填绝对路径
```

只读，不占额度，不改变手账任何一条记录。

## 九、已知边界

- 只做词面匹配，同义改写要靠同义词表（表里没有就搜不到）；
- 手账里的引用只在学习管线侧解析（`study_journal_get` 的 `refs`），核心拿到的是 id 和片段；
- 桥的用处是"她想不起来去看手账"时的兜底——实测里她更常直接调学习管线的工具，这是对的，桥不抢主线；
- 群聊与别人的私聊不搜（同学习管线的可见性规则）。
