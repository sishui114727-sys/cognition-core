# 学习手账桥（cognition-study → cognition-core）

只读桥，0.24.0 新增。解决一件事：**手账写在隔壁插件里，但「回忆」在核心这边。**

```text
学习管线（cognition-study）                 记忆核心（cognition-core）
  journal/ledger.jsonl   ──────只读──────→  StudyBridge → cognition_study_search
  readings.jsonl         ──────只读──────→             → cognition_recall 尾注
  notes.jsonl            ──────只读──────→
```

## 一、为什么不做成"写进核心"

```text
1. 手账是学习记录，不是对话记忆。混进 events.jsonl 会让"经历"变成大杂烩，
   核心的提取、归纳、注入都会跟着变脏。
2. 核心的写入口只有一条（宿主回调 + after-response）。从另一个插件直接写它的
   JSONL，会破坏"只有一个写入者"的前提，这是最难查的一类问题。
3. 去掉学习管线时，核心不该留下半条残废的记忆。
```

所以桥的方向是单向的：**核心读手账，手账不写核心。**

## 二、打开

```text
设置 → 认知核心 → 读取学习手账（studyBridgeEnabled，默认关）
设置 → 认知核心 → 学习管线数据目录（studyDataDir，一般留空）
```

留空时按同级目录找：`<QQA 安装目录>/data/plugin-data/cognition-study`。
装在别处（比如别的盘）才需要填绝对路径。

## 三、打开后有什么

```text
cognition_study_search   按关键词检索手账 / 稿件 / 札记
                         返回：类型、日期、标题、id、摘要片段、命中分
                         未命中会告诉你"现存 X 篇"，而不是空手让你猜
cognition_recall         结果尾部附「学习管线里也有」三行（标题 + 日期 + id）
                         记忆侧判定没有可靠内容时，若手账有明确命中会改口说清楚
```

只用标题和 id，不搬正文：回忆的预算是以百 token 计的，正文该由模型按需去取。

## 四、检索口径

```text
切词       中文二元组、英文与数字按词
权重       标题命中 3 分 / 正文命中 1 分
          近义词命中：标题 2 分 / 正文 1 分（比原词低一档）
门槛       原词覆盖率 ≥ 0.3；原词一个都没命中时要求 ≥ 0.67
排序       分数高者先出，同分按记录顺序
上限       默认 5 条，最多 10 条
```

手账是追加修订的，桥会按修订链折成一条线程、只取最新一版：账本里原条目和它的 `revises` 都在，
不折的话同一个意思会被端上来两三次，而且先出的往往是被改掉的那一版。库存按"篇"（线程数）报，
修订单独计数（`journalAmendments`），命中里带 `thread` 指回原条目。

同义词表直接复用核心的 `src/synonyms.js`（不另做一份）：问"疲惫"能捞回写着"累了"的那篇，
问"密钥"能不能捞回"凭证"取决于表里有没有这一组——表里没有，桥不会自己编。
命中里带 `expanded > 0` 时会标注"近义说法命中"，不假装是原词匹配。

## 五、边界（都是刻意的）

```text
读哪些文件    <data>/journal/ledger.jsonl、<data>/readings/readings.jsonl、<data>/notes/notes.jsonl
              （这层目录结构是照着 live 数据核过的；第一版写成 <data>/readings.jsonl，稿件永远 0 篇）
只读          不写手账、不改索引、不动账本
默认关闭      装了不会自动改变回忆结果
坏数据不炸    账本读到坏行跳过那一行；整个目录不存在就是"现存 0"
不缓存过期   按 (mtime, size) 失效，账本一变就重读；没变不重读
不解决写回    手账里想引用核心的记忆，仍然只能靠对话
```

## 六、它没解决的问题

```text
1. 语义检索：桥只做词面匹配，同义改写（"凭证"vs"密钥"）搜不到
2. 反向：从手账跳到核心的记忆，需要人工在对话里说
3. 跨机：手账在另一台机器上时，桥看不到
```

前两条本版不做。第三条可以用 `studyDataDir` 指到同步盘，但延迟和一致性由同步软件负责，
桥不假装能处理。
