# 上下文与指代设计（0.22.1）

更新时间：2026-10-29
目标：解决「代词指谁」和「图片表情与上下文割裂」两个具体问题，并说明它与《核心工艺：以全量原文为地基》四层模型的关系。

---

## 一、诊断：不是模型笨，是我们把证据丢了

三处丢失，按影响排序：

### 1. L0 存的是「合并成一坨」的对话

`src/host.js` 的 `after-response` 原来这样写：

```js
const userText = trigger.filter((e) => !e.self).map((e) => e.text).join('\n');
text: `${userText}\n→ ${content}`
```

群里一轮唤醒常带 2–5 条消息，全被拼进一个字符串，**谁说的**只剩 `participants` 里一串 id。
于是「他」在记忆里没有候选集：检索回来的是没有主语的段落。

### 2. media 在入口就被丢掉

宿主 `store.js` 的入站消息本来带：

```js
{ mid, ts, senderId, senderName, text, reply, media: [{ kind, url, file, faceId, summary }] }
```

写入 L0 时只留了 `text`，图片/表情退化成 `[图片]`。
所以「这个表情」在事后没有任何锚点：不知道是哪张、谁发的、在哪条消息里。

### 3. 检索注记没有说话人

`context-pack.js` 原来渲染：

```text
E: <summary 或 text 截断>
C: <statement> (confidence=0.8)
```

没有名字、没有媒体、没有引用。召回内容本身回答不了「谁说的」。

### 4. 另外：注入默认是关的

`injectContextEnabled=false`。现状里 cognition-core 根本没参与每轮上下文，
live 上的「记忆感」来自宿主自己的【过去状态】与 mem 插件。
所以这次改动要先解决「数据有没有」，再谈「注入开不开」。

---

## 二、指代：给候选，不替模型下结论

### 原则

不做代词改写。「他把这个发给我」自动改写成「张三把图 3 发给李四」，
一旦改写错，模型会**更自信地错**——比重写前更糟。

我们做的是：把候选按时间摆出来，让模型用它已有的语言能力判断。

### 实现

`src/turns.js`：

```text
buildTurns(entries)      每条消息 → { mid, self, senderId, senderName, ts, text, media, reply }
renderTurn(turn)         「张三(QQ:20001)：[引用 李四：…]正文 [表情#178]」
collectReferents(turns)  { speakers(近→远,≤3), lastMedia, lastQuote }
describeReferents(...)   【指代参考】三行以内
hasPronoun(text)         他/她/它/这个/那个/上面/刚才…
```

L0 事件新增 `metadata.turns`（≤8 条，每条 ≤240 字符，媒体 ≤4 条），
旧事件不受影响，检索时无 `turns` 就走原文截断。

### 注入形态

```text
【指代参考】
最近发言者（由远到近）：李四 / 张三
最近一条媒体：张三 发的表情#178
最近一次引用：张三：你看这个表情笑死
```

成本：3 行 64 字符 ≈ 52 token，**且只在当前这句含代词时才注入**。
一句「笑死」不加这段——这条有测试。

## 三、图片/表情：先保住锚点，再谈理解

1. **存**：`media[{kind,faceId,summary,url,file}]` 进 L0。`url` 只做本地定位，不注入。
2. **渲染**：`[表情#178]` / `[图片「summary」]` / 无描述时 `[图片]`。
3. **引用链**：`reply` 保留被引用者与原话；被引用的媒体随该消息一起进上下文。
4. **不知道就说不知道**：没有 `summary` 的图，不生成描述、不猜内容。
   要真正「看懂图」，需要视觉通道——这是外部能力，不在本插件内伪造。

## 四、与「全量原文为地基」四层模型的对照

| 你的分层 | cognition-core 现状 | 差什么 |
|---|---|---|
| L0 原始层 | `events.jsonl`，append-only | 本轮补上 turns/media/reply；历史事件无法补齐 |
| L1 观察层（raw_ref） | `Cognition` / `Episode`，带 `evidenceEventIds` | 缺 `raw_ref` 的显式字段名，语义等价；可加别名 |
| L2 主题层（topic_key + superseded） | `cognition.metadata.key` + `status(candidate/stable/contested)` | 缺 `superseded_by` 指针；contested 只记矛盾文本 |
| L3 会话层 | 无（宿主有自己的【过去状态】） | 没做 session summary，也不该抢宿主的活 |
| 注入层四段拼装 | 只做 ③ 检索段 | ①常驻在宿主人设；②近期在宿主窗口；④摘要缺 |

**结论**：cognition-core 是「L0 增强 + ③ 检索段」，不是整套四层。
强行把 ①②④ 也塞进插件，会和宿主已有的窗口/人设打架——这正是"多套记忆双写"的老坑。

## 五、下一步（按性价比）

```text
P1（本轮完成）  L0 记 turns/media/reply；检索带说话人；指代参考块
P2  拒识阈值   没有稳定认知且事件分低于 τ → 不注入（幻觉主要来源之一）
P2  superseded_by  Cognition 加显式演化指针，contested 时可回溯"被谁取代"
P3  混合检索    BM25(现有 substring) + 向量，RRF 融合；人名/型号强制关键词
P3  mem_get_raw 按 eventId 取原文片段，配合 raw_ref 深挖
P4  导出/恢复   L0 zip + manifest 校验和 + 索引重建（L0 不可重建）
```

P2 的拒识是治幻觉的第一优先级：宁可这轮不注入，也不塞不相关的东西。

## 六、代价

```text
L0 体积      每条事件多存 turns（实测均值待线上统计，上限 8×240 字符）
注入 token   仅代词轮 +50 tok；非代词轮 0
正确性风险   不做改写，因此不会引入"改写错"
不解决       没有视觉通道时，图片内容本身仍然不可知
```
