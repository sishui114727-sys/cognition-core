# 发布包与混淆说明

版本：`0.23.22`  
适用于：社区包（`cognition-core-0.23.22-community.zip`）与 GitHub 包（`cognition-core-0.23.22-github.zip`）

---

## 1. 包里有什么

```text
plugin/            cognition-core 插件（index.js 与 src/ 已混淆）
docs/              使用说明、炸机说明、完成度说明、更新说明、数据收集协议、风险说明
scripts/           聚合数据导出脚本 public-data-export.mjs + schema
LICENSE            专有软件声明（UNLICENSED，禁止二次开发）
NOTICE.zh-CN.md    许可说明：允许运行，禁止修改与再分发
README.md          入口
```

**不含**：`data/`、任何 `*.jsonl` 聊天记录、配置里的主人 QQ、日志、截图、Cookie。

## 2. 混淆做了什么

工具：`javascript-obfuscator`（构建期使用，插件运行时零依赖）。

```text
compact                    去掉空白与换行
identifierNamesGenerator   局部变量名改成十六进制
stringArray + rc4          字符串抽到数组并 base64/rc4 编码
controlFlowFlattening      控制流平坦化（阈值 0.4）
splitStrings               长字符串切片重组
stringArrayRotate/Shuffle  字符串数组轮转与打乱
```

覆盖范围：`index.js` + `src/**`。

**没有覆盖**：`panel/**`（面板是只读 UI，保持明文让用户能看懂它在读什么）、
`docs/`、`scripts/`、`package.json`、`plugin.json`。

## 3. 混淆没做什么（别误会）

```text
不是加密     没有密钥，代码在宿主进程里必须可执行，任何人拿到文件都能反混淆
不是授权控制  不能阻止修改与再分发
不是性能优化  混淆后体积约 2 倍，执行略慢（<10%，实测无感）
```

一句话：**它只让"打开看看逻辑"变麻烦，不构成安全边界。** 想真正保护逻辑，只能不放出来。

## 4. 为什么仍然做

理由很实际：

```text
1. 阻止搜索引擎/复制党把逻辑当模板抄（大多数爬取只处理明文）
2. 降低"改一个常量就当成自己作品发布"的概率
3. 让 issue 报告更可能描述现象而不是直接贴源码
```

这三条都是**降低摩擦**，不是**防止恶意**。

## 5. 构建与自检

```text
node scripts/build-release.mjs
```

流程：

```text
1. 用 build-dist 产出标准分发包
2. 剔除 devDependencies（插件运行时零依赖）
3. 混淆 index.js + src/**
4. node --check 每个文件
5. 把混淆后的 src 拷进临时目录，跑完整测试套件（200 条）
   —— 混淆改坏代码是这类发布最容易出的事故，所以自检不过就不出包
6. 附文档/脚本/许可证，压缩成两个 zip
7. 写 release-manifest.json（版本、混淆配置、体积、zip 清单）
```

跳过测试用 `--skip-tests`，只出目录不压缩用 `--no-zip`。**正式发布不要用 `--skip-tests`。**

## 6. 混淆后的可维护性代价

```text
线上报错堆栈是混淆后的名字，排查要靠"复现步骤 + 版本号 + 日志"而不是行号
用户无法自行改代码修 bug —— 这正是作者不提供二次开发支持的原因之一
调试时必须用未混淆的仓库版本，两边行为要一致（自检保证这一点）
```

## 7. 验证发布包是否完整

```text
node scripts/smoke-install.mjs <解压目录>     目录结构、相对导入是否全部可解析
node scripts/scan-release.mjs --dir <解压目录>  是否含 QQ 号/邮箱/绝对路径等
```

两个脚本都在仓库里，发布前必须跑过。
